## Задача

Необходимо реализовать ограничение количества входящих запросов с использованием паттерна **Rate Limiting**. Цель — защитить приложение от чрезмерного числа запросов от партнёров и обеспечить возврат ошибки 429 при превышении лимита.

## Рассуждения и подход
При анализе задачи были учтены следующие моменты:
- Ограничение задаётся по IP-адресу отправителя с помощью директивы `$binary_remote_addr`.
- Требуется обеспечить не более 10 запросов в минуту от одного клиента.
- Для конфигурации был использован модуль **ngx_http_limit_req_module**. В качестве источника информации использована официальная документация Nginx:  
  [https://nginx.org/en/docs/http/ngx_http_limit_req_module.html#limit_req_zone](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html#limit_req_zone)

Изучив документацию, было подтверждено, что Nginx поддерживает задание лимита в запросах в минуту с использованием `r/m` для значений ниже 1 запроса в секунду.

## Итоговая конфигурация Nginx
```nginx
http {
    # Ограничение: максимум 10 запросов в минуту от одного IP
    limit_req_zone $binary_remote_addr zone=by_ip:10m rate=10r/m;
    
    # Настройка upstream для балансировки нагрузки
    upstream backend_servers {
        server backend1.example.com;
        server backend2.example.com;
        server backend3.example.com;
    }
    
    server {
        listen 80;
        
        location / {
            # Применяем ограничение с небольшим запасом для кратковременных пиков
            limit_req zone=by_ip burst=3 nodelay;
            
            proxy_pass http://backend_servers;
        }
    }
    
    # Возвращать код 429 при превышении лимита
    limit_req_status 429;
}
```

## Результат
Была создана конфигурация, которая ограничивает входящий трафик до 10 запросов в минуту от одного клиента.
При превышении лимита возвращается HTTP 429 (Too Many Requests).
