# Анализ и обоснование перехода на GraphQL

## Анализ проблемы

Проблема заключается в том, что REST API сервиса client-info порождает большое количество запросов в рамках одного пользовательского процесса. Потребителям данных приходится делать несколько отдельных запросов для получения различных частей данных клиента (например, данные о клиенте, его документах, родственниках). Это приводит к росту нагрузки на сервис и неэффективному использованию ресурсов, особенно в условиях высокой нагрузки.

## Обоснование выбора GraphQL

GraphQL является подходящим решением в данной ситуации. Он позволяет сократить количество запросов за один пользовательский процесс. Клиенты могут запрашивать только те данные, которые действительно необходимы в конкретном сценарии, без необходимости агрегировать несколько отдельных запросов. Это положительно сказывается на производительности и снижает потребление ресурсов.

При дальнейшем росте системы и увеличении числа сценариев использования REST API становится всё менее удобным решением. В системе насчитывается значительное количество атрибутов (около 500), что создаёт множество возможных комбинаций запрашиваемых данных. GraphQL позволяет избежать проблем REST API в таких условиях и предотвращает дублирование данных при передаче.

## Итоговое решение

На основании анализа REST API была спроектирована следующая схема GraphQL:

```graphql
type Query {
  client(id: ID!): Client
}

type Client {
  id: ID!
  name: String
  age: Int
  documents: [Document]
  relatives: [Relative]
}

type Document {
  id: ID!
  type: String
  number: String
  issueDate: String
  expiryDate: String
}

type Relative {
  id: ID!
  relationType: String
  name: String
  age: Int
}
```

Эта схема позволяет гибко формировать запросы и получать только необходимые данные в рамках одного запроса. Например:

```graphql
query {
  client(id: "123") {
    name
    documents {
      type
      number
    }
    relatives {
      name
      relationType
    }
  }
}
```

## Заключение

Использование GraphQL в данном случае обеспечивает оптимизацию взаимодействия между потребителями данных и сервисом client-info, снижает нагрузку и повышает гибкость архитектуры.
